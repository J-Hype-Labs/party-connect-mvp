# 지도 기반 업체 탐색 — 설계 (구현 보류)

> 상태: **설계만 있음, 구현하지 않음.** 2026-11-10 PM 결정: Notion MVP 범위에는 있으나 11/15 목표(실제 신청 접수 MVP와 실거래 검증)가 우선이라 후순위.
> 이 문서는 나중에 착수할 때 바로 쓸 수 있게 방안·선행 조건·테스트 계획만 남긴다.

## 1. 목표와 제약

- 목표: 파티커넥트 페이지에서 지도 위에 업체(파티가 열리는 장소)를 보고, 마커를 눌러 그 업체의 파티를 확인·신청한다.
- 제약: **서버(DB) 변경 없이** 한다. `stores`에는 `address`, `address_detail`, `region`만 있고 위경도가 없다. `GET /parties`는 `venue`, `address`, `region`을 내려준다.
- 따라서 좌표는 브라우저에서 **카카오맵 JS SDK의 주소 검색(Geocoder)** 으로 구한다.

## 2. 방식

1. **지연 로딩**: 사용자가 "지도" 탭을 처음 열 때만 SDK를 불러온다. `https://dapi.kakao.com/v2/maps/sdk.js?appkey=<JS키>&libraries=services&autoload=false`, 로드 후 `kakao.maps.load(cb)`.
2. **업체 단위 묶기**: 현재 필터를 통과한 파티를 `address` 기준으로 묶어 업체 목록을 만든다(같은 주소 = 한 마커, 파티 N개).
3. **좌표 구하기**: 묶음마다 `new kakao.maps.services.Geocoder().addressSearch(address, cb)`. 동시 3건 이하로 순차 처리하고, 결과는 `localStorage`(`partyconnect:geocode:v1`, `address → {lat, lng, savedAt}`, 30일)에 캐시한다. 실패한 주소는 마커 없이 "위치를 찾지 못한 업체" 목록에 남긴다.
4. **마커·시트**: 마커 클릭 시 하단 시트(모바일) 또는 사이드 패널(데스크톱)에 업체명, 주소, 파티 카드를 보여 주고, 카드의 "파티 신청하기"는 기존 상세 모달을 그대로 연다. 신청 흐름은 새로 만들지 않는다.
5. **필터 연동**: 지역·요일·카테고리·검색 상태가 바뀌면 마커를 다시 그린다(좌표 캐시는 재사용). 지도 범위는 마커 전체에 맞춘다(`setBounds`).

## 3. 화면

- 파티 목록 위에 `목록 | 지도` 토글. 기본은 목록이며, **목록은 항상 사용 가능한 기본 화면**이다(지도는 추가 기능).
- 지도 높이는 모바일 60vh, 데스크톱 520px. 320px 가로 넘침이 없어야 한다(`tests/mobile-layout.spec.js` 기준 유지).
- 접근성: 지도 컨테이너에 `role="region"` + `aria-label="업체 지도"`, 마커 정보는 항상 아래 목록으로도 제공(스크린리더·키보드 사용자는 목록 사용). SDK 로드 실패 시 "지도를 불러오지 못했어요. 목록으로 볼 수 있어요." 안내 후 목록으로 전환.
- 사용자 입력·서버 문자열은 `textContent`/React 텍스트로만 그린다(`innerHTML`, 카카오 InfoWindow의 HTML 문자열 금지).

## 4. 테스트 계획 (실제 카카오 호출 없이)

- Playwright에서 `**/dapi.kakao.com/**/sdk.js`를 스텁으로 대체(`kakao.maps.load`, `Map`, `Marker`, `LatLngBounds`, `services.Geocoder.addressSearch`만 흉내). 스텁 Geocoder가 주소별 좌표/실패를 돌려주게 한다.
- 검증: 지도 탭 최초 진입 시에만 SDK 요청, 같은 주소 파티는 마커 1개, 필터 변경 시 마커 수 변화, 좌표 캐시 재사용(두 번째 진입에서 Geocoder 호출 0), 주소 실패 시 "위치를 찾지 못한 업체" 표시, 마커/시트의 신청 버튼이 기존 상세 모달을 연다, SDK 로드 실패 시 목록으로 폴백.

## 5. 선행 조건 — **사용자 승인 대기**

| 항목 | 내용 |
|---|---|
| 카카오 JavaScript 키 | 카카오 디벨로퍼스 앱의 JavaScript 키 확인(없으면 발급). 이 키는 브라우저에 노출되는 값이며 도메인 제한으로 보호한다. REST/Admin 키는 쓰지 않는다. |
| 웹 도메인 등록 | 앱 설정의 플랫폼(Web)에 `https://j-hype-labs.github.io` 등록. 로컬 개발용으로 `http://localhost:3000`도 필요 |
| 카카오맵 사용 설정 | 앱에서 카카오맵(지도/로컬) 사용 설정이 꺼져 있으면 SDK가 거절한다. 콘솔에서 켜야 하는지 확인 필요 |
| 사용량 한도 | 주소 검색 호출 한도를 콘솔에서 확인. 캐시와 업체 단위 묶기로 호출을 줄이는 설계지만 한도는 확인된 값을 근거로 판단한다 |
| 키 보관 위치 | `PARTYLINK_CONFIG`처럼 저장소의 공개 설정값으로 둘지 승인 필요(비밀 키가 아님) |

위 항목은 코드로 해결할 수 없고 계정 소유자의 콘솔 작업과 승인이 필요하다. 승인 전에는 구현하지 않는다.

## 6. 이후 개선(범위 밖)

- 서버에 `stores.latitude/longitude`를 추가하고 관리자 점포 등록 시 좌표를 저장하면 브라우저 Geocoder와 캐시가 필요 없어진다(DB/서버·관리자 화면 담당과 협의 필요).
- "내 주변" 정렬은 위치 권한 요청이 필요하므로 별도 결정.
- 업체 단독 상세 페이지는 MVP에서 제외(파티 상세 모달로 충분, Notion '업체 상세 정보' 요건은 '부분 충족'으로 기록).
