# 수동 E2E 체크리스트 (관리자 화면 기준)

실제 카카오 로그인과 배포된 서버로 **신청 → 선정 → 방문 인증 → 미션 제출 → 보완 요청 → 재제출 → 최종 승인 → 적립금 차감**을 끝까지 한 번 돌려 보는 문서입니다. 자동 테스트는 서버를 mock 하므로, 이 문서가 실서버 연결을 확인하는 유일한 방법입니다. 소요 시간은 30~40분입니다.

> ⚠️ **실서비스 DB로 하는 테스트입니다.** 모든 테스트 데이터 이름에 `[E2E]`를 붙이고, 실제 점포·게스트와 섞이지 않게 하세요. 적립금 원장(`deposit_histories`)은 수정·삭제할 수 없으므로 테스트 충전·차감 기록은 남습니다.

## 0. 준비물

| 항목 | 내용 |
|---|---|
| 관리자 계정 | 카카오 로그인 후 `admins` 테이블에 등록된 계정 (`INSERT INTO admins (user_id, note) VALUES ('<auth.users.id>', ...)`) |
| 게스트 계정 | 관리자와 **같은 계정으로 해도 되지만**, 화면이 헷갈리면 다른 카카오 계정(또는 다른 브라우저 프로필)을 쓰세요 |
| 사이트 | 게스트: `https://j-hype-labs.github.io/party-connect-mvp/` · 관리자: 같은 주소 뒤에 `admin/` |
| DB 확인 | Supabase 대시보드 → SQL Editor (아래 쿼리는 모두 읽기 전용 `SELECT`) |
| API 호출 | 터미널 `curl` (5단계 미션 제출에만 사용. 사이트에 미션 제출 화면이 아직 없음) |

> 사이트 주소·Supabase 프로젝트 주소는 `admin/index.html`의 `PARTYLINK_CONFIG`에 있는 값을 쓰세요. 아래 `<프로젝트>`는 `https://<ref>.supabase.co`입니다.

### 시간 맞추기 (중요)

방문 인증은 **파티 시작 60분 전 ~ 종료 시각 사이**에만 됩니다(서버 규칙). 모집 마감은 시작 이전이어야 하고, 신청은 모집 마감 전에만 됩니다. 그래서 파티를 이렇게 만듭니다. (지금이 14:00이라면)

| 항목 | 값 | 이유 |
|---|---|---|
| 시작 | 14:50 | 시작 60분 전부터 방문 인증 가능 → 만들자마자 인증 가능 |
| 모집 마감 | 14:35 | 이 시각 전에 신청해야 함 |
| 종료 | 17:00 | 이 시각 전에 방문 인증해야 함 |

모집 마감까지 약 35분 안에 **신청(2단계)** 을 끝내면 됩니다. 선정 이후 단계는 마감 후에도 됩니다.

## 1. 점포 만들고 파티 열기 (관리자)

| # | 할 일 | 기대 결과 | 확인 |
|---|---|---|---|
| 1-1 | `/admin/` 접속 → 카카오 로그인 | 신청 관리 화면이 보임. "권한이 없습니다"가 나오면 `admins` 등록 안 됨 | 화면 |
| 1-2 | **점포·적립금 → 새 점포**: 이름 `[E2E] 테스트 바`, 사업자번호 `999-99-99999`(이미 쓰였으면 다른 값), 기본 수수료 `10000` | 목록에 점포가 생기고 적립금 `0원` | 화면 |
| 1-3 | **파티 → 새 파티**: 점포 `[E2E] 테스트 바`, 제목 `[E2E] 수동 테스트`, 정원 `2`, 인당 수수료 비움(→10,000원), 위 "시간 맞추기" 값, 등록 상태 **바로 모집 시작(OPEN)** | 목록에 `모집 중`으로 표시, 인원 `0 / 2` | 화면 |

DB 확인:
```sql
SELECT s.id AS store_id, s.name, s.prepaid_balance, p.id AS slot_id, p.status, p.fee_per_guest, p.starts_at, p.recruit_deadline
FROM stores s JOIN party_slots p ON p.store_id = s.id
WHERE s.name LIKE '[E2E]%' ORDER BY p.created_at DESC;
```
기대: `prepaid_balance = 0`, `status = OPEN`, `fee_per_guest = 10000`. 이후 쿼리에서 쓰도록 `store_id`, `slot_id`를 메모하세요.

## 2. 카카오 로그인 → 신청 (게스트)

| # | 할 일 | 기대 결과 | 확인 |
|---|---|---|---|
| 2-1 | 사이트 접속 → 카카오 로그인 | 로그인 성공, 상단에 닉네임. (데모 모드면 `?demo=1` 없이, 배포 주소로 열었는지 확인) | 화면 |
| 2-2 | 목록에서 `[E2E] 수동 테스트` 찾아 신청: 이름, 연락처(`01012345678` 형식), 개인정보 동의 | 신청 완료. **내 신청 내역**에 `신청` 상태 | 화면 |
| 2-3 | 같은 파티에 다시 신청 | "이미 신청한 파티입니다." | 화면 |

DB 확인:
```sql
SELECT a.id AS application_id, a.status, a.visit_code, a.fee_amount, g.name, g.phone
FROM applications a JOIN guests g ON g.id = a.guest_id
WHERE a.slot_id = '<slot_id>';
```
기대: 행 1개, `status = APPLIED`, `fee_amount` 비어 있음. `application_id`를 메모하세요.

## 3. 선정 (관리자)

| # | 할 일 | 기대 결과 | 확인 |
|---|---|---|---|
| 3-1 | **신청 관리** → 파티 필터 `[E2E]…` → 신청 카드의 **선정** | 토스트 "선정했습니다.", 상태 `선정` | 화면 |
| 3-2 | 파티 목록으로 이동 | 인원 `1 / 2` | 화면 |
| 3-3 | (게스트) **내 신청 내역** 새로고침 | 상태 `선정`, **방문 인증 코드**가 보임 | 화면 |

DB: 2단계 쿼리 재실행 → `status = APPROVED`, `fee_amount = 10000`(수수료 스냅샷), `approved_at` 채워짐. 코드는 3-3 화면에서 메모하세요.

## 4. 방문 인증 (관리자)

| # | 할 일 | 기대 결과 | 확인 |
|---|---|---|---|
| 4-1 | 신청 카드 **방문 인증** → 틀린 코드 `WRONG` 입력 | 오류 메시지(코드를 확인하라는 안내), 상태 그대로 | 화면 |
| 4-2 | 3-3의 방문 코드 입력 → 인증 | "방문을 인증했습니다.", 상태 `방문 인증` | 화면 |

DB: `status = VISITED`, `visited_at` 채워짐. 시간대 밖이면 "허용 시간 외" 계열 오류가 나오니 "시간 맞추기"를 다시 확인하세요.

## 5. 미션 제출 (게스트, 터미널)

사이트에 미션 제출 화면이 없어서 API를 직접 부릅니다. 게스트 브라우저 개발자 도구 → Application → Local Storage → `sb-<ref>-auth-token`의 `access_token` 값을 복사하세요. 이 토큰은 **본인 로그인 토큰이므로 어디에도 공유·저장하지 마세요.**

```bash
curl -sS -X POST "<프로젝트>/functions/v1/partylink-api/applications/<application_id>/mission" \
  -H "Authorization: Bearer <access_token>" \
  -H "apikey: <PARTYLINK_CONFIG의 supabaseAnonKey>" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.instagram.com/p/E2E-TEST-1/"}'
```
기대: `{"application_id":"…","status":"MISSION_SUBMITTED"}`. `http(s)://`가 아닌 URL은 400.

| 확인 | 기대 |
|---|---|
| 관리자 신청 카드 | 상태 `미션 제출`, 미션 링크가 보이고 클릭하면 새 탭에서 열림. 버튼 **최종 승인**, **보완 요청** |
| 게스트 내 신청 내역 | `미션 검수 중` |

## 6. 보완 요청 → 재제출

| # | 할 일 | 기대 결과 | 확인 |
|---|---|---|---|
| 6-1 | (관리자) **보완 요청** → 확인 | 상태가 `방문 인증`으로 돌아감. 안내문대로 **적립금은 차감되지 않음** | 화면 |
| 6-2 | (게스트) 5단계 `curl`을 URL만 `.../E2E-TEST-2/`로 바꿔 다시 실행 | `MISSION_SUBMITTED`, 관리자 화면에 **새 링크**가 보임 | 화면 |

DB:
```sql
SELECT status, mission_url, mission_submitted_at, settled_at, deposit_history_id
FROM applications WHERE id = '<application_id>';
```
6-1 직후: `status = VISITED`. 6-2 직후: `mission_url`이 `E2E-TEST-2`, `settled_at` / `deposit_history_id`는 여전히 비어 있음.

## 7. 최종 승인 → 적립금 차감

적립금이 `0원`인 지금은 **먼저 부족 오류를 확인**하고, 충전한 뒤 다시 승인합니다.

| # | 할 일 | 기대 결과 | 확인 |
|---|---|---|---|
| 7-1 | (관리자) **최종 승인** → 확인 대화상자에 점포명과 `10,000원`이 보이는지 확인 → 승인 | **"적립금 잔액이 부족합니다."** 오류, 상태 `미션 제출` 유지 | 화면 |
| 7-2 | **점포·적립금 → `[E2E] 테스트 바` → 충전**: 금액 `30000`, 입금자명 `[E2E] 홍길동` | 적립금 `30,000원` | 화면 |
| 7-3 | 다시 **최종 승인** | 성공, 상태 `완료` | 화면 |
| 7-4 | 점포 **내역** 열기 | 맨 위 `차감 -10,000원 → 잔액 20,000원`, 아래에 `충전 +30,000원` | 화면 |
| 7-5 | 승인 버튼 연타 / 이미 `완료`된 카드 | 두 번째 차감이 일어나지 않음, 완료 카드에는 버튼 없음 | 화면 |

DB:
```sql
SELECT type, amount, balance_before, balance_after, depositor_name, application_id, created_at
FROM deposit_histories WHERE store_id = '<store_id>' ORDER BY id;
SELECT prepaid_balance FROM stores WHERE id = '<store_id>';
SELECT status, fee_amount, settled_at, completed_at, deposit_history_id FROM applications WHERE id = '<application_id>';
```
기대:
- 원장 2행: `CHARGE 30000 (0→30000)`, `DEDUCT 10000 (30000→20000, application_id 연결)`
- `prepaid_balance = 20000`
- 신청: `status = COMPLETED`, `fee_amount = 10000`, `settled_at`·`completed_at`·`deposit_history_id` 채워짐
- `DEDUCT` 행은 신청당 **1개뿐**

## 8. 추가 확인 (시간 있을 때)

| 항목 | 방법 | 기대 |
|---|---|---|
| 비관리자 접근 | 관리자 등록이 안 된 계정으로 `/admin/` 접속 | "권한이 없습니다" |
| 로그아웃 상태 | 로그아웃 후 `/admin/` | 로그인 안내만 보임 |
| 환불 | 점포 **환불** `5000` → 잔액보다 큰 금액 | `15,000원`이 됨 / 큰 금액은 오류 |
| 반려 | 파티에 다른 계정으로 신청 → **반려**(사유 입력) | 상태 `반려`, 사유가 카드에 보임 (게스트 화면에 사유가 표시되는지도 확인) |
| 노쇼 | 시작 이후 `선정` 상태 신청에 **노쇼** | 상태 `노쇼`, 관리자 **게스트** 화면에서 노쇼·벌점 증가 |

## 9. 정리

- 파티 `[E2E] 수동 테스트`: **파티 → 취소**
- 점포 `[E2E] 테스트 바`: **점포·적립금 → 수정**에서 비활성화(가능한 경우). 남은 적립금은 **환불**로 0원으로 만들기
- 원장 기록은 남습니다. 삭제하지 마세요(수정·삭제는 서버가 막습니다). 데이터를 지워야 한다면 운영자와 상의하세요.

## 알려진 제약

- 사이트에 **게스트용 미션 제출 화면이 없습니다.** 5·6단계는 API 호출로 대체합니다.
- 보완 요청 **사유는 저장되지 않습니다**(상태만 되돌림).
- 점주용 화면이 없어 선정·방문 인증·승인은 모두 관리자 화면에서 대행합니다.
