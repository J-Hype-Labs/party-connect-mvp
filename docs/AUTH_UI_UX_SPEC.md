# PartyConnect 인증 UI/UX 상세 명세

- 버전: 1.1
- 기준일: 2026-11-08
- 상위 기준: AUTH_IMPLEMENTATION_SPEC.md
- 공통 UI 코드: js/auth-ui.js
- 공통 인증 상태: js/auth-service.js
- 콜백 페이지: auth/callback/index.html

## 1. 목표

카카오 로그인을 PartyConnect 서비스 안에서 자연스럽게 이어지는 사용자 흐름으로 만든다. 사용자는 로그인 때문에 파티 탐색 맥락을 잃거나 같은 파티를 다시 찾아서는 안 된다.

로그인 성공, PartyConnect 가입 완료, 파티 신청 접수, 파티 선정 완료는 각각 다른 상태다.

## 2. 디자인 시스템

현재 메인 페이지의 CSS 기준:

| 토큰 | 값 | 역할 |
|---|---|---|
| Primary | #E11D48 | 주요 CTA, 활성 상태 |
| Secondary | #FB7185 | 보조 강조 |
| Accent | #F59E0B | 보조 강조 |
| Background | #FFFFFF | 기본 배경 |
| Surface | #FAFAFA | 보조 표면 |
| Text | #18181B | 본문 |
| Muted | #71717A | 보조 텍스트 |
| Border | #E4E4E7 | 경계선 |
| Kakao button | #FEE500 | 카카오 공식 버튼 목표 배경 |
| Kakao text | #191919 | 카카오 버튼 글자 |

- 글꼴: Pretendard
- 본문: 14~16px
- 보조 문구: 12~13px
- 주요 버튼: 48~52px
- 터치 영역: 최소 44×44px
- 데스크톱 모달: 최대 너비 420px
- 모바일 모달: 좌우 여백 각 16px 이상
- 모달 radius: 16px
- 필드 간격: 16px

### 현재 구현과 차이

현재 js/auth-ui.js의 KakaoLoginButton은 흰색 배경이며 52px 높이다. 공식 카카오 로그인 버튼의 시각 가이드와 비교해 배경·로고·여백을 최종 확인해야 한다. 목표 디자인 토큰을 이미 적용했다고 보고하지 않는다.

## 3. 화면 A: 비로그인 상태

- 공개 파티 목록과 상세 정보는 로그인 없이 탐색할 수 있다.
- 헤더에 로그인 진입점을 표시한다.
- 파티 신청 또는 마이페이지 등 회원 전용 기능을 실행할 때 인증을 요청한다.
- 로그인 모달을 열어도 뒤에 있던 파티 상세 화면과 필터 상태를 유지한다.

## 4. 화면 B: 카카오 로그인 모달

구성:
1. 닫기 버튼
2. PartyConnect 브랜드
3. 제목: 파티에 참여할 준비가 됐나요?
4. 설명: 카카오 계정으로 간편하게 시작하고 마음에 드는 파티에 신청하세요.
5. 카카오 로그인 버튼
6. 이용약관 및 개인정보 처리방침 링크

버튼:
- 기본: 카카오로 계속하기
- 처리 중: 카카오 로그인 연결 중...
- 처리 중 버튼 비활성화, 중복 클릭 방지
- 실제 live=false일 때 현재 버튼은 비활성화된다. 설정 누락을 성공처럼 숨기지 말고, 사용자에게 서비스 준비 상태를 이해할 수 있는 안내를 제공해야 한다.

네이버 등 미지원 소셜 로그인 버튼을 추가하지 않는다.

## 5. 화면 C: OAuth callback 처리

현재 auth/callback/index.html은 로딩 화면을 표시하고 Supabase 세션을 확인한다.

목표 화면:
- 브랜드 표시
- 로딩 인디케이터
- 문구: 카카오 로그인을 확인하고 있어요.
- 보조: 잠시 후 원래 화면으로 이동해요.

오류 상태에는 다음이 필요하다.
- 로그인 재시도
- 원래 화면으로 돌아가기
- 내부 기술 오류나 인증 토큰을 노출하지 않기
- 무한 로딩 금지

현재 callback 페이지는 error state에서도 AuthProcessingScreen만 표시하며, 재시도/홈 이동 핸들러가 사용자에게 연결되어 있는지 추가 검증이 필요하다.

## 6. 화면 D: 최초 가입 동의

현재 js/auth-ui.js에 OnboardingScreen 컴포넌트가 존재한다.

항목:
- 필수: 서비스 이용약관 동의
- 필수: 개인정보 수집·이용 동의
- 선택: 이벤트·혜택 소식 받기

동작:
- 필수 두 항목을 모두 체크해야 시작하기 활성화
- 선택 마케팅 동의는 기본 미선택
- 각 문서 링크는 실제 정책 문서로 연결
- 서버 저장 성공 후에만 가입 완료 처리
- 저장 실패 시 선택 상태를 보존하고 재시도
- 선택 동의를 거절해도 서비스 가입이 가능해야 함

현재 callback page는 신규 가입 상태에서 메인 페이지의 onboarding query로 이동하지만, 두 페이지에서 OnboardingScreen이 실제 렌더링되는지와 가입 완료 후 복귀가 연결되는지 검증이 필요하다. 컴포넌트가 존재한다는 이유로 화면 연결 완료로 표시하지 않는다.

## 7. 화면 E: 로그인 후 원래 파티 복귀

사용자가 파티 A 상세에서 신청을 누른 뒤 로그인했다면 다음 순서여야 한다.

파티 A 상세 → 신청하기 → 카카오 로그인 → 최초 동의(필요한 경우) → 파티 A 신청서

보존할 값:
- 내부 returnPath
- partyId
- intent
- createdAt

보안:
- 내부 허용 경로만 허용
- 외부 URL 리다이렉트 차단
- 복귀 상태 만료 시간 적용
- 전화번호·이름·토큰을 URL에 넣지 않음
- 정상 복귀 또는 취소 후 임시 상태 제거

현재 auth-service는 sessionStorage에서 복귀 정보를 소비하고 callback 페이지가 이를 사용한다. 최초 가입 분기에서 복귀 정보가 사라지지 않는지 반드시 검증한다.

## 8. 화면 F: 신청서와 완료

신청 폼:
- 신청자 이름
- 연락처
- 선택한 파티 요약
- 필요한 일정
- 파티 신청 목적의 개인정보 수집·이용 동의

검증:
- 이름·연락처 형식 검증
- 필수 동의 확인
- 모집 상태·정원·마감은 서버가 최종 판단
- 제출 중 버튼 비활성화
- 오류 후 입력값 유지
- 서버 성공 응답 전 완료 화면 금지

완료 문구:
- 제목: 신청이 접수되었어요.
- 보조: 마이페이지에서 신청 상태를 확인할 수 있어요.
- CTA: 내 신청 확인하기 / 다른 파티 둘러보기

APPLIED는 신청 접수이지 선정 확정이 아니다.

## 9. 화면 G: 프로필 메뉴와 마이페이지

로그인 후:
- 프로필 또는 닉네임
- 마이페이지
- 내 신청 내역
- 로그아웃

마이페이지:
- API에서 반환된 본인 신청만 표시
- 로딩·빈 상태·오류 상태를 분리
- 취소 가능 여부를 상태에 따라 표시
- 다른 회원 데이터는 노출하지 않음

로그아웃:
- 처리 중 상태 표시
- Supabase signOut 성공 후 비로그인 UI 전환
- 실패 시 기존 로그인 상태 유지 및 재시도 안내

## 10. 오류 문구

| 상황 | 문구 | 행동 |
|---|---|---|
| 사용자 취소 | 로그인이 취소되었어요. | 원래 화면 유지 |
| 인증 실패 | 카카오 로그인에 실패했어요. 다시 시도해 주세요. | 재시도 |
| 연결 실패 | 로그인 서버에 연결할 수 없어요. | 재시도 |
| 세션 만료 | 로그인 시간이 만료됐어요. 다시 로그인해 주세요. | 재로그인 |
| 필수 동의 누락 | 필수 항목을 확인해 주세요. | 누락 항목 강조 |
| 동의 저장 실패 | 가입 정보를 저장하지 못했어요. | 입력 유지·재시도 |
| 중복 신청 | 이미 신청한 파티예요. | 내 신청 이동 |
| 모집 마감 | 모집이 마감된 파티예요. | 상세 유지 |
| 서버 오류 | 요청을 처리하지 못했어요. 잠시 후 다시 시도해 주세요. | 재시도 |
| 로그아웃 실패 | 로그아웃하지 못했어요. 다시 시도해 주세요. | 로그인 상태 유지 |

SQL 오류, stack trace, token 등 내부 정보는 사용자에게 표시하지 않는다.

## 11. 접근성

- ESC 및 명시적 닫기 버튼
- 모달 배경 스크롤 잠금
- focus trap과 닫은 후 포커스 복귀
- 키보드 Tab/Shift+Tab/Enter/Space 지원
- 입력 label과 오류 메시지 연결
- 로딩 상태 aria-live
- 색상만으로 상태 전달 금지
- prefers-reduced-motion 지원
- 최소 44×44px 터치 영역
- 카카오 버튼 accessible name 제공

## 13. QA 증거와 완료 기준

구현 PR에 다음 캡처를 첨부한다.
- 데스크톱/모바일 로그인 모달
- callback 로딩 및 오류
- 최초 가입 동의
- 로그인 후 원래 파티 신청서
- 신청 완료
- 마이페이지
- 로그아웃 성공/실패

실제 DOM 캡처와 브라우저 테스트를 사용한다. 정적 목업이나 JSX 파싱만으로 UX 완료를 선언하지 않는다.
