# PartyConnect 인증 UI/UX 상세 명세

- 버전: 1.0
- 기준일: 2026-11-08
- 인증 구현 기준: AUTH_IMPLEMENTATION_SPEC.md

## 1. 디자인 원칙

1. 기존 PartyConnect의 rose 계열 브랜드와 Pretendard를 유지한다.
2. 로그인은 파티 탐색을 막는 진입 장벽이 아니라 신청 시 필요한 단계로 둔다.
3. 로그인 성공, 가입 완료, 신청 접수는 서로 다른 상태로 표시한다.
4. 사용자가 로그인 전에 보던 파티와 화면 맥락을 복원한다.
5. 로딩·빈 상태·오류·재시도 상태를 모두 디자인한다.
6. 데모와 실서비스의 결과를 혼동시키지 않는다.
7. 화면 문구는 간결한 한국어로 쓰고 내부 API 용어를 노출하지 않는다.

## 2. 디자인 토큰

현재 메인 페이지 CSS에서 확인되는 기준값:

| 토큰 | 값 | 사용 |
|---|---|---|
| Primary | #E11D48 | 주요 CTA, 활성 상태 |
| Secondary | #FB7185 | 보조 강조, hover |
| Accent | #F59E0B | 이벤트·주의성 보조 강조 |
| Background | #FFFFFF | 기본 배경 |
| Surface | #FAFAFA | 카드·모달 보조 배경 |
| Text | #18181B | 본문 |
| Muted | #71717A | 보조 텍스트 |
| Border | #E4E4E7 | 경계선 |
| Kakao | #FEE500 | 카카오 로그인 버튼 배경 |
| Kakao text | #191919 | 카카오 버튼 텍스트 |

- 기본 글꼴: Pretendard
- 제목: 굵은 weight, 짧고 명확한 문장
- 본문: 14~16px
- 보조 문구: 12~13px
- 주요 버튼: 높이 48~52px
- 모든 터치 컨트롤: 최소 44×44px
- 데스크톱 모달: 최대 너비 420px
- 모바일 모달: 화면 너비에서 좌우 16px 이상 여백
- 모달 radius: 16px
- 필드 간격: 16px
- 섹션 간격: 24px

이 값은 인증 화면의 목표 기준이다. 실제 CSS와 다른 값이 있으면 구현 PR에서 차이를 기록하고, 근거 없이 브랜드 전체를 교체하지 않는다.

## 3. 인증 화면 상태

### A. 비로그인 상태

- 공개 파티 탐색과 상세 열람은 허용한다.
- 헤더에는 로그인 진입점을 표시한다.
- 신청·마이페이지 등 회원 전용 행동에서 인증을 요청한다.
- 로그인 요구 때문에 사용자가 보고 있던 상세 화면을 닫거나 초기화하지 않는다.

### B. 로그인 모달

구성 순서:

1. 닫기 버튼
2. PartyConnect 브랜드 표시
3. 제목: 파티에 참여할 준비가 됐나요?
4. 설명: 카카오 계정으로 로그인하고 관심 있는 파티를 신청하세요.
5. 카카오 로그인 버튼
6. 이용약관과 개인정보 처리방침 링크

카카오 로그인 버튼:
- 배경 #FEE500
- 글자 #191919
- 공식 사용 가이드에 맞는 카카오 자산
- 높이 52px
- 전체 너비
- 클릭 즉시 중복 클릭 방지
- 로딩 중 문구: 카카오 로그인 연결 중...

네이버 로그인 버튼이나 미지원 소셜 로그인 버튼을 표시하지 않는다.

### C. OAuth 처리 중

- 중앙 로딩 인디케이터
- 문구: 카카오 로그인을 확인하고 있어요.
- 보조 문구: 잠시 후 원래 화면으로 이동해요.
- 무한 로딩 금지
- timeout 또는 callback 오류 시 재시도/처음 화면 이동을 제공한다.

### D. 최초 가입 동의

제목: 파티커넥트에 오신 걸 환영해요.

항목:
- 필수: 서비스 이용약관 동의
- 필수: 개인정보 수집·이용 동의
- 선택: 이벤트·혜택 소식 받기

동작:
- 필수 항목을 모두 확인해야 시작하기 활성화
- 선택 동의는 기본 미선택
- 각 문서는 별도 링크로 열 수 있어야 함
- 서버 저장 성공 후에만 가입 완료 표시
- 저장 실패 시 선택 상태를 보존하고 재시도 가능

가입 폼에 인증과 무관한 정보 항목을 추가하지 않는다. 생년월일·나이·연령 확인 필드나 관련 동의·배지를 만들지 않는다.

### E. 로그인 후 복귀

- 인증 전 선택한 partyId를 유지한다.
- 로그인과 온보딩이 끝나면 동일 파티 상세/신청 흐름으로 돌아간다.
- 사용자가 다시 검색하거나 파티를 선택하게 만들지 않는다.
- 복귀 데이터가 만료되었거나 잘못된 경우 안전한 파티 목록으로 안내한다.

### F. 신청서

필드:
- 신청자 이름
- 연락처
- 선택한 파티 정보
- 필요한 일정 선택
- 파티 신청 목적의 개인정보 수집·이용 동의

필드 요구:
- 이름과 연락처의 필수 여부는 사업 정책에 맞춰 확정한다. 현재 backend API는 name, phone, agree를 요구한다.
- 전화번호 입력은 숫자 중심으로 안내하고 하이픈 입력을 허용한다.
- 오류는 필드 가까이에 표시한다.
- 입력값은 서버 오류 후 유지한다.
- 신청 버튼 클릭 시 진행 중 상태를 표시하고 중복 제출을 막는다.
- 서버 성공 응답 전 완료 화면을 표시하지 않는다.

완료 문구:
- 제목: 신청이 접수되었어요.
- 보조: 마이페이지에서 신청 상태를 확인할 수 있어요.
- CTA: 내 신청 확인하기 / 다른 파티 둘러보기

신청 접수와 파티 선정 확정을 같은 의미로 쓰지 않는다.

### G. 회원 헤더 및 마이페이지

로그인 상태:
- 프로필 또는 닉네임 표시
- 마이페이지 진입
- 내 신청 내역
- 로그아웃

모바일:
- 프로필 터치 영역 최소 44×44px
- 메뉴가 화면을 벗어나지 않게 한다.
- 좁은 화면에서는 바텀시트 사용 가능

마이페이지:
- 실제 API가 반환한 본인 신청만 표시
- 상태 배지와 취소 가능 여부를 구분
- 로딩과 빈 상태를 별도 처리
- API 오류를 '신청 내역 없음'으로 오인하지 않게 한다.

## 4. 오류 문구와 복구 행동

| 상황 | 문구 | 행동 |
|---|---|---|
| 사용자가 로그인 취소 | 로그인이 취소되었어요. | 원래 화면 유지 |
| 인증 실패 | 카카오 로그인에 실패했어요. 다시 시도해 주세요. | 재시도 |
| 연결 실패 | 로그인 서버에 연결할 수 없어요. | 재시도 |
| 세션 만료 | 로그인 시간이 만료됐어요. 다시 로그인해 주세요. | 로그인 |
| 필수 동의 누락 | 필수 항목을 확인해 주세요. | 누락 항목 강조 |
| 가입 저장 실패 | 가입 정보를 저장하지 못했어요. | 입력 유지 후 재시도 |
| 이미 신청 | 이미 신청한 파티예요. | 내 신청 이동 |
| 모집 마감 | 모집이 마감된 파티예요. | 상세 유지 |
| 신청 서버 오류 | 신청을 처리하지 못했어요. 잠시 후 다시 시도해 주세요. | 재시도 |
| 로그아웃 실패 | 로그아웃하지 못했어요. 다시 시도해 주세요. | 로그인 상태 유지 |

기술 상세, SQL 오류, token, stack trace는 사용자 화면에 표시하지 않는다.

## 5. 모달과 접근성

- ESC와 명시적 닫기 버튼 제공
- 모달 표시 중 배경 스크롤 잠금
- focus trap 적용
- 닫은 후 열기 버튼으로 focus 복귀
- 키보드 Tab/Shift+Tab/Enter/Space 지원
- 필드 label과 오류 문구 연결
- 로딩 상태는 aria-live 또는 적절한 상태 속성으로 알림
- 색상만으로 상태 전달 금지
- prefers-reduced-motion 존중
- 최소 터치 영역 44×44px
- 카카오 버튼과 아이콘에 명확한 accessible name 제공

## 6. 반응형 검증 기준

| 폭 | 주요 확인 |
|---|---|
| 320px | 모달 가로 넘침, 버튼 잘림, 키보드 겹침 |
| 375px | 일반 iPhone 폭, 입력과 CTA |
| 390px | 현재 주요 모바일 테스트 폭 |
| 768px | 태블릿 레이아웃 |
| 1280px | 데스크톱 모달 정렬 |
| 1440px | 넓은 화면 콘텐츠 폭 |

브라우저:
- Chromium desktop
- Mobile Chrome
- WebKit / Mobile Safari

iOS Safari 키보드 표시 후 CTA가 가려지지 않는지 실제 기기 또는 신뢰 가능한 브라우저 테스트로 확인한다.

## 7. UI/UX QA 증거

구현 PR에는 다음 증거를 첨부한다.

- 데스크톱 로그인 모달
- 모바일 로그인 모달
- 최초 가입 동의
- OAuth 처리 중
- 인증 실패
- 로그인 후 파티 신청서
- 신청 완료
- 마이페이지
- 로그아웃 성공/실패

각 화면은 실제 DOM 렌더링 캡처여야 한다. 정적 목업만으로 완료 판정하지 않는다.
